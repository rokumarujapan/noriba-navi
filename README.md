# のりばナビ (Noriba Navi)

Google マップのバス経路案内は「どこの系統に乗るか」までは教えてくれても、多くのターミナルで
「どの番号ののりば（乗車ホーム）から乗るか」までは教えてくれません。のりばナビは、東京都交通局
（都営バス）が公開している公式 GTFS-JP オープンデータをもとに、行き先ごとの正しい系統・のりば番号・
次の発車時刻・時刻表を、実際の地図の上に表示するアプリです。

現在対応しているのは 品川駅高輪口 発の5方面（五反田駅 / 六本木ヒルズ / 大井競馬場前 / 目黒駅前 /
新宿駅西口）のみのプロトタイプです。データ抽出の仕組み自体は他の起点・他の路線にもそのまま拡張できます
（下記「データを拡張する」を参照）。

## できること

- 行き先を選ぶと、その行き先専用の系統番号・のりば番号・現在時刻から見た「次の3便」が一目でわかる
- 平日／土曜／日曜祝日の3パターンの時刻表をすべて閲覧できる
- 実際の地図（OpenStreetMap）を常時表示し、のりば位置・目的地・（対応区間は）実走行ルートを重ねて表示
- 出発地点（起点）を3通りの方法で選択可能:
  1. 現在地取得（GPS）
  2. 地図をタップして任意の地点を選択
  3. 駅名・地名のテキスト検索（OpenStreetMap Nominatimによるジオコーディング）
  選択した地点が対応エリア（現状は品川駅高輪口周辺 半径1km以内のみ）に入っていればそのエリアの
  データに自動で切り替わり、対応エリア外の場合はその旨を表示した上で、現在対応中のエリアのデータを
  引き続き表示します（品川駅から離れた場所にいても、閲覧自体は可能です）。
- 訪問先をお気に入り登録（端末内保存）
- 日本語 / English / 中文 / 한국어 の4言語切り替え
- 同じのりば・同じ系統番号でも行き先が異なる便が存在する実例（反96系統、品97系統で確認済み）を
  踏まえ、行き先表示（ヘッドサイン）を必ず確認するよう案内

## なぜこの構成なのか（Claude Artifact → GitHub Pages への移行）

このプロジェクトは元々 Claude の Artifact 機能（1枚の自己完結した HTML ファイル）上でプロトタイプを
作っていましたが、次の理由から実運用に近い形にするため GitHub Pages 用の複数ファイル構成に移行しました。

1. **地図タイル（Google Maps / OpenStreetMap）が読み込めない** — Claude Artifact のホスティング環境には
   厳しい CSP（コンテンツセキュリティポリシー）があり、外部の地図タイルサーバーへの読み込みがブロック
   されます。これは Google Maps の課金設定とは無関係の、プラットフォーム側の制約でした。GitHub Pages は
   ただの静的サイトなのでこの制約はありません。
2. **位置情報（GPS）を安定して使うには、本物のトップレベル HTTPS ページが必要** — Claude のプレビュー
   （iframe埋め込み）内では Geolocation API が不安定になることがありますが、公開URLを直接開く本物の
   ページであれば問題なく動作します。
3. **1ファイルという構造の限界** — すべての路線・行き先・時刻表を1つの HTML に手書きで埋め込んでいく
   方式では、機能を追加しても見た目が大きく変わらず、拡張性・保守性の面で早晩限界が来ます。
   `js/data.js` / `js/app.js` / `css/style.css` を分離し、データは再実行可能な抽出スクリプト
   (`scripts/extract_gtfs.py`) から生成する形にすることで、今後 23区内の他エリアへ拡張しやすくしています。

## ファイル構成

```
noriba-navi/
├── index.html            アプリ本体（画面構造）
├── css/style.css         スタイル（スマホ表示を前提としたフルスクリーンUI）
├── js/data.js            実データ本体（GTFS-JPから抽出済み。品川駅高輪口 発 5方面）
├── js/app.js             アプリのロジック（地図描画・検索・お気に入り・GPS・多言語切替）
├── scripts/extract_gtfs.py  GTFS-JPの生データからjs/data.jsを生成/拡張するPythonスクリプト
└── README.md             このファイル
```

外部ライブラリは Leaflet.js（地図描画）のみで、cdnjs 経由の CDN 読み込みです。ビルド作業は不要で、
`index.html` を開くだけで動作します。

## GitHub Pages で公開する手順

すでに GitHub アカウントをお持ちとのことなので、次の流れで公開できます。

1. **新しいリポジトリを作る**
   GitHub の右上「+」→「New repository」から、既存の `fuji-noren` とは別の新しいリポジトリを作成します
   （例: `noriba-navi`）。Public / Private どちらでも GitHub Pages は使えますが、無料プランでは
   Public リポジトリの方が設定がシンプルです。「Add a README file」のチェックは外したままで構いません
   （このプロジェクトに README.md が含まれているため）。

2. **このフォルダの中身をリポジトリに追加する**
   最も簡単なのは GitHub の Web 画面からのドラッグ＆ドロップです。
   作成したリポジトリのページで "uploading an existing file" というリンク（またはリポジトリ内の
   「Add file」→「Upload files」ボタン）をクリックし、ダウンロードした `noriba-navi` フォルダの中身
   （`index.html`、`css`フォルダ、`js`フォルダ、`scripts`フォルダ、`README.md`）をまとめてドラッグ＆
   ドロップしてアップロードし、「Commit changes」を押します。
   ※ フォルダ構造（`css/style.css` のようにサブフォルダに入っていること）はそのまま維持してください。
   Web画面へのドラッグ＆ドロップでもサブフォルダ構造は保持されます。

   ターミナル操作に慣れている場合は、代わりに次のコマンドでも同じことができます。
   ```
   git init
   git add .
   git commit -m "Initial commit: のりばナビ プロトタイプ"
   git branch -M main
   git remote add origin https://github.com/<あなたのユーザー名>/noriba-navi.git
   git push -u origin main
   ```

3. **GitHub Pages を有効にする**
   リポジトリページの上部タブから「Settings」→ 左メニューの「Pages」を開きます。
   「Build and deployment」の「Source」を **Deploy from a branch** にし、Branch を **main** / フォルダを
   **/ (root)** に設定して「Save」を押します。

4. **公開URLを確認する**
   数十秒〜数分待つと、同じ Pages 設定画面の上部に
   `https://<あなたのユーザー名>.github.io/noriba-navi/`
   という形の公開URLが表示されます。このURLをスマートフォンのブラウザで開けば、実際に街で使える形で
   動作確認できます（GPSボタンを押すと位置情報の利用許可を求められます）。

5. **更新するときは**
   ファイルを修正したら、同じように Web 画面でファイルを再アップロード（上書き）するか、
   `git add . && git commit -m "..." && git push` を実行すれば、GitHub Pages に自動的に反映されます
   （反映まで数十秒〜数分かかることがあります）。

## データを拡張する（他の起点・他の路線を追加する）

現在は 品川駅高輪口 発の5方面のみです。他の起点（新宿駅、渋谷駅、錦糸町駅など）や他の系統を追加する
には、`scripts/extract_gtfs.py` を使います。

1. 東京都交通局の最新の GTFS-JP zip を ODPT (https://www.odpt.org/) から取得し、展開します。
2. `scripts/extract_gtfs.py` 冒頭の `ROUTES_TO_EXTRACT` リストに、追加したい行き先ごとに
   「出発のりばの stop_id」「行き先表示（ヘッドサイン）の正確な文字列」「id・名前」を追記します。
   - 出発のりばの stop_id は `stops.txt` から、対象の停留所名・のりば番号（`platform_code`列）で
     絞り込んで特定してください（親駅の stop_id ではなく、のりばごとの子 stop_id を使う必要があります）。
   - 行き先表示は `stop_times.txt` の `stop_headsign` 列（空の場合は `trips.txt` の `trip_headsign`）
     と完全一致している必要があります。**同じのりば・同じ系統番号でも行き先が異なる便が混在する
     ケースが実際にあります**（例: 品97系統 のりば7 は「新宿駅西口」行きと「青山一丁目駅前」行きの
     両方が発着します）。系統番号だけで絞り込むと誤ったデータになるため、必ず行き先表示で絞り込む
     設計にしてあります。
3. `python3 scripts/extract_gtfs.py --gtfs-dir <展開したGTFSフォルダ> --out js/data.js` を実行します。
4. 目的地の座標（`destLatLon`）と、経路のポリライン（`shape`、五反田駅方面の例のみ実装済み）は
   このスクリプトでは自動生成していません。`stops.txt` から該当停留所の緯度経度を調べて手で埋めるか、
   `shapes.txt` の該当 `shape_id` の点列を追加してください。

将来的にエリアを23区全体に広げる場合、すべてのデータを1つの `data.js` に埋め込み続けるとファイルが
巨大になりすぎるため、どこかの時点で簡易的なバックエンド（例: 検索APIやデータベース）を用意する方式へ
切り替えることを推奨します。現状のスケール（数駅・数十方面程度まで）であれば `data.js` のままで
問題ありません。

## データの出典・ライセンス

本アプリが使用するバス運行データは、東京都交通局（Tokyo Metropolitan Bureau of Transportation）が
公共交通オープンデータ協議会（ODPT: https://www.odpt.org/）を通じて公開している GTFS-JP オープンデータ
（フィードバージョン: `20260912_031154`）に基づいています。ライセンスは **CC BY 4.0** です。
このデータを利用・再配布する際は、出典として東京都交通局および公共交通オープンデータ協議会を明記して
ください（本アプリのフッターに常時表示しています）。

地図タイルは OpenStreetMap のデータを使用しており、地図上にも帰属表示（© OpenStreetMap contributors）
を表示しています。出発地点のテキスト検索には OpenStreetMap の Nominatim ジオコーディングサービスを
使用しています。Nominatim の利用規約上、大量・高頻度のリクエストは想定されていません（個人利用の
検索頻度であれば問題ありません）。将来的に検索頻度が大幅に増える場合は、別のジオコーディングサービス
への切り替えを検討してください。

## 既知の制約

- 対応エリアは品川駅高輪口発の5方面のみ（プロトタイプ段階）。品川から離れた場所（例: 小金井市など）
  で現在地を取得した場合、GPS自体は正しく動作していても「対応エリア外」と表示されるのが正しい挙動です
  （その場所のバスデータをまだ持っていないため）。誤動作ではありません。
- GPSの精度は端末・電波状況に依存します（屋内やビル街ではWi-Fi測位により実際の位置から数百m〜
  ずれることがあります）。
- 時刻表は平日／土曜／日曜祝日の3区分で表示していますが、年末年始など `calendar_dates.txt` の例外的な
  運行日は現時点では反映していません。
- 実走行ルート（ポリライン）は五反田駅方面のみ実装済みで、他の4方面は起点・のりば・目的地の点のみの
  表示です。
- GPS機能は「品川駅高輪口から半径1km以内かどうか」を判定するのみで、対応エリア外にいる場合の代替案内
  （最寄りの対応起点の提案など）はまだありません。
